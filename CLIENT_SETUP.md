# Инструкция заказчику

Сервис один раз в 21:00 по Лондону запускает вечернюю сессию подготовки трёх постов.
Сначала приходит оригинал. Только после кнопки «Создать пост» обычный текст
передаётся в LLM и полностью переводится на английский с точечной заменой только
контекста автора. Текст не пересказывается и может быть опубликован через Buffer:
одним постом в LinkedIn и X Premium, а в Threads — тредом при необходимости.

## Доступы

Нужно подготовить:

1. Telegram-бота у [@BotFather](https://t.me/BotFather): `BOT_TOKEN`.
2. `OWNER_CHAT_ID`: после запуска написать боту `/id`.
3. Отдельный рабочий Telegram-аккаунт, его `api_id` и `api_hash` с
   [my.telegram.org/apps](https://my.telegram.org/apps).
4. `OPENAI_API_KEY` для перевода и адаптации текста через `gpt-5.6-terra`.
5. Buffer с подключёнными LinkedIn, X и Threads.
6. Подтверждённые сведения об авторе для `AUTHOR_FACTS`.

## Настройки

```text
MAX_POST_CHARS=1500
THREAD_ITEM_CHARS=250
THREAD_MAX_ITEMS=10
MANUAL_MAX_POST_CHARS=3000
X_PREMIUM=true
PLANNING_TIME=21:00
PUBLISH_TIMES=09:00,14:00,19:00
DAILY_POSTS=3
ITEMS_PER_SLOT=1
TIMEZONE=Europe/London
SYNC_MONTHS=3
AUTO_SYNC=false
```

`sources.txt` содержит согласованные источники. Бот формирует общий пул:
берёт по одному самому старому необработанному материалу каждого источника и
сортирует их от старых дат к новым. В 21:00 начинаются три последовательные
итерации. После готовности одного поста бот сразу запускает следующую. Новый круг
источников формируется после исчерпания текущего пула.

Если на сыром материале нажать **Пропустить**, следующий материал из пула
приходит сразу в рамках той же итерации. Цепочка продолжается, пока владелец не
сохранит черновик на завтра. Три готовых поста автоматически публикуются на
следующий день в 09:00, 14:00 и 19:00 по Лондону.
После каждого дневного слота Telegram присылает короткий результат: успешную
публикацию с фрагментом поста либо видимую ошибку.

Если у выбранного источника есть фото, после `Готово на завтра` бот отдельно
спросит: поставить в очередь **с картинкой** или **без картинки**. У обычного
текста этого вопроса нет. Выбор хранится в PostgreSQL до дневной публикации.

`AUTO_SYNC=false` оставь и после полного сбора: база создаётся один раз и затем
расходуется. Одинаковый нормализованный непустой текст из разных каналов
сохраняется только один раз.

## Авторизация Telegram

На сервере:

```bash
docker compose run --rm --build bot python -m repost.ingest login
```

Код и пароль двухэтапной проверки вводятся в терминале. Получившийся
`data/repost.session` нельзя передавать третьим лицам или добавлять в git.

## Безопасная первая проверка

Вместо `@channel` ниже нужно указать один username уже из `sources.txt`.

```bash
docker compose run --rm --build bot \
  python -m repost.ingest backfill --days 7 --sources @channel --limit 1
docker compose up -d --build
```

В Telegram вызови `/test @channel`. После проверки:

```bash
docker compose down
docker compose run --rm --build bot python -m repost.ingest backfill --months 3
```

Снова выполни `docker compose up -d --build`, оставив `AUTO_SYNC=false`.
Telegram может выдать `FloodWait` или ограничить
аккаунт без отдельного предварительного предупреждения, поэтому первый canary
нельзя пропускать.

## Кнопки

У сырого текста:

- **Создать пост** — только сейчас вызывается LLM; обычный текст переводится,
  а не превращается в новую идею;
- **Пропустить** — материал закрывается без расхода токенов, следующий из пула
  приходит сразу.

Voice/audio/video передаются вместе с сырым материалом во время выдачи и не
расшифровываются. Если нужен пост по медиаматериалу, владелец пишет собственный текст.

У готового текста:

- **Готово на завтра** — сохранить пост в следующий свободный слот;
- **Редактировать руками** — прислать полный новый текст ответом;
- **Редактировать с AI** — написать Terra инструкцию и получить полностью
  обновлённую версию; действие можно повторять;
- **Пересобрать Threads с AI** — не менять LinkedIn/X master, а заново сделать
  связную последовательность Threads: hook, story/value points и payoff, каждый
  отдельным законченным сообщением до 250 символов;
- **Другой материал** — отклонить готовый черновик и продолжить текущую итерацию;
- **Закончить на сегодня** — остановить оставшиеся итерации; уже готовые посты
  сохранят своё расписание.

Постоянная кнопка **Создать пост** работает отдельно от вечерней сессии:

- **Накидывать из базы** — одна обычная итерация, но итоговая публикация идёт
  сразу, а не завтра;
- **Написать свой текст** — сохранить присланный текст без AI. Затем доступны
  `Опубликовать сейчас`, `Standard Transform`, ручное редактирование,
  AI-редактирование и отмена.

`Standard Transform` выполняет только по отдельному нажатию три шага: перевод на
английский, исправление фактов Mike/Vahue и смысловое сжатие до 1500 символов,
только если текст длиннее. Одновременно создаётся отдельный Threads-план. До
`Standard Transform`, `Пересобрать Threads с AI` или AI-редактирования токены LLM
не расходуются. AI-редактор работает с текущей версией и сохраняет её язык, если
перевод прямо не попросили. После ручного изменения master Terra автоматически
пересобирает только Threads, не переписывая LinkedIn/X.

Telegram Bot API не умеет автоматически вставлять произвольный длинный текст в
поле ввода пользователя. Поэтому ручное редактирование показывает текущую полную
версию прямо в ForceReply-сообщении и сразу открывает поле ответа.

Фото публикуется через Buffer во все три канала. Для этого `PUBLIC_BASE_URL`
должен указывать на production Vercel URL; бот отдаёт Buffer прямую HTTPS-ссылку,
не раскрывая Telegram bot token. Buffer принимает изображение меньше 10 МБ.

## Команды

```text
/test @channel — один canary-материал без LLM
/next          — вручную начать ещё одну итерацию из общего пула
/stats         — состояние очереди
```
