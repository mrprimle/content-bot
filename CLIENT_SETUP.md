# Инструкция заказчику

Сервис дважды в день показывает материалы из выбранных Telegram-источников.
Сначала приходит оригинал. Только после кнопки «Создать пост» он передаётся в
LLM, превращается в английский пост длиной до 250 символов и может быть
опубликован через Buffer.

## Доступы

Нужно подготовить:

1. Telegram-бота у [@BotFather](https://t.me/BotFather): `BOT_TOKEN`.
2. `OWNER_CHAT_ID`: после запуска написать боту `/id`.
3. Отдельный рабочий Telegram-аккаунт, его `api_id` и `api_hash` с
   [my.telegram.org/apps](https://my.telegram.org/apps).
4. `OPENAI_API_KEY` для генерации и опциональной расшифровки voice.
5. Buffer с подключёнными LinkedIn и X. Threads можно оставить на паузе.
6. Подтверждённые сведения об авторе для `AUTHOR_FACTS`.

## Настройки

```text
GENERATOR_MODE=rewrite
MAX_POST_CHARS=250
POST_TIMES=10:00,18:00
ITEMS_PER_SLOT=2
TIMEZONE=Europe/London
SYNC_MONTHS=3
AUTO_SYNC=false
```

`sources.txt` уже содержит 34 согласованных источника. Бот формирует общий пул:
берёт по одному самому старому необработанному материалу каждого источника и
сортирует их от старых дат к новым. В 10:00 приходят два материала, в 18:00 —
следующие два, то есть четыре базовых материала в день. Новый круг формируется
после исчерпания текущего пула.

Если нажать **Пропустить**, следующий материал из пула приходит сразу. Такая
замена не входит в базовые четыре, поэтому фактическое число сообщений за день
может быть больше четырёх.

`AUTO_SYNC=false` нужен только для безопасной первой проверки; после полного
сбора его нужно заменить на `true`.

## Авторизация Telegram

На сервере:

```bash
docker compose run --rm --build bot python -m repost.ingest login
```

Код и пароль двухэтапной проверки вводятся в терминале. Получившийся
`data/repost.session` нельзя передавать третьим лицам или добавлять в git.

## Безопасная первая проверка

Вместо `@channel` ниже нужно указать один username уже из `sources.txt`.

```bash
docker compose run --rm --build bot \
  python -m repost.ingest backfill --days 7 --sources @channel --limit 1
docker compose up -d --build
```

В Telegram вызови `/test @channel`. После проверки:

```bash
docker compose down
docker compose run --rm --build bot python -m repost.ingest backfill --months 3
```

Поставь `AUTO_SYNC=true` в `.env` и снова выполни `docker compose up -d --build`.
Дальше бот сам повторяет сбор через три календарных месяца и корректно учитывает
переход Лондона между GMT/BST. Telegram может выдать `FloodWait` или ограничить
аккаунт без отдельного предварительного предупреждения, поэтому первый canary
нельзя пропускать.

## Кнопки

У сырого текста:

- **Создать пост** — только сейчас вызывается LLM;
- **Пропустить** — материал закрывается без расхода токенов, следующий из пула
  приходит сразу.

Voice/audio/video передаются вместе с сырым материалом во время выдачи. У
voice/audio дополнительно есть **Расшифровать**: только распознавание речи и
создание 2–4 предложений запускаются по нажатию. Для voice/video также можно
написать собственный текст.

У готового текста:

- **Опубликовать** — отправить в настроенные каналы Buffer;
- **Редактировать** — прислать новый текст ответом;
- **Пропустить** — ничего не публиковать и сразу показать следующий материал.

Кнопки повторной LLM-генерации нет.

## Команды

```text
/test @channel — один canary-материал без LLM
/next          — следующие два материала из общего пула
/stats         — состояние очереди
```
